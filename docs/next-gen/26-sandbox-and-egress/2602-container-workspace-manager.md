# 2602 — Контейнерный workspace-менеджер

**Фаза:** P4 · **Оценка:** XL · **Зависит от:** 1103
**Файлы:** `packages/execution/src/workspace/container-workspace-manager.ts`

## Контекст
Интерфейс `WorkspaceManager` уже допускает несколько реализаций (`git-worktree`, `static`).
Контейнер — третий режим для недоверенного кода.

## Объём
- Запуск контейнера с примонтированным рабочим деревом, лимитами CPU/RAM/PID, отдельным пользователем.
- Исполнение `shell_exec` и верификационных команд внутри контейнера, а не на хосте.
- Гарантированная уборка контейнера при любом исходе, включая аварийное завершение воркера.

## Критерии приёмки
- [ ] Существующая политика инструментов остаётся первым рубежом; контейнер — второй.
- [ ] Отсутствие среды контейнеризации → понятная ошибка конфигурации, а не падение прогона.
- [ ] Накладные расходы измерены и задокументированы.

## Тесты
- Интеграция (по метке, требует docker): прогон в контейнере; уборка после kill -9.
