# 0305 — HTTP-транспорт: таймауты, ретраи, джиттер

**Фаза:** P0 · **Оценка:** M · **Зависит от:** 0303
**Файлы:** `packages/llm/src/transport/http.ts`

## Контекст
Сейчас `fetchWithTimeout` (`packages/llm/src/index.ts:126`) даёт один общий таймаут и не
различает соединение и генерацию; ретраев нет вовсе.

## Задача
Единый транспорт с раздельными таймаутами, ограниченными ретраями и корректной отменой.

## Объём
- `connectTimeoutMs` и `requestTimeoutMs` раздельно; для локальных моделей второй существенно больше.
- Ретрай только для `retriable` ошибок; экспонента + full jitter; уважение `retryAfterMs`.
- Проброс внешнего `AbortSignal` (интеграция с `packages/execution/src/cancellation/propagate-abort.ts`).
- Обязательное освобождение таймеров в `finally` (текущее поведение сохранить).

## Критерии приёмки
- [ ] Отмена извне прекращает запрос и не оставляет висящих таймеров.
- [ ] Число попыток ограничено конфигурацией, каждая попытка логируется с `attempt`.
- [ ] Секреты не попадают в логи (проверка через `redactSecrets`).

## Тесты
- Юнит с фиктивным `fetch`: 429 + Retry-After; 500 ×3 → отказ; отмена в середине; таймаут.
