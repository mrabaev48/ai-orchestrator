# 1004 — Пул воркеров вместо одиночного цикла

**Фаза:** P1 · **Оценка:** L · **Зависит от:** 0803, 1002, 1003
**Файлы:** `apps/worker/src/worker-runner.ts`, `apps/worker/src/worker-pool.ts` (новый)

## Контекст
Сейчас воркер — один цикл `runCycle` с backoff (`apps/worker/src/worker-runner.ts`),
а `workflow.workerCount` используется только в валидации конфига
(`packages/shared/src/config/runtime-config.ts:473`).

## Задача
Пул из N параллельных исполнителей в процессе; каждый берёт элемент очереди, держит heartbeat,
исполняет прогон через `createProjectRuntime`, завершает элемент.

## Критерии приёмки
- [ ] `workerCount` наконец влияет на исполнение и провалидирован против политики планировщика.
- [ ] Один упавший исполнитель не роняет пул и не блокирует остальных.
- [ ] Backoff при пустой очереди сохранён (существующее поведение idle/error backoff).
- [ ] Метрика `run_concurrency{instance, project}`.

## Тесты
- Интеграция: 8 воркеров, 50 элементов очереди, все обработаны ровно один раз.
