# 0607 — Принудительные бюджеты на фактической стоимости

**Фаза:** P0 · **Оценка:** M · **Зависит от:** 0606, 0102
**Файлы:** `packages/application/src/budgets/budget-guard.ts`

## Задача
Ввести многоуровневые бюджеты (инстанс / тенант / проект / агент / прогон) с мягким порогом
(алерт) и жёстким (стоп), опирающиеся на `run_cost`, а не на оценки.

## Объём
- Проверка перед дорогой операцией и после её завершения.
- Дневной бюджет проекта — источник `SchedulingBlockReason: 'budget_exhausted'` (1003).
- Событие `cost.threshold.reached` для уведомлений (2003/2004).

## Критерии приёмки
- [ ] Превышение жёсткого лимита останавливает прогон детерминированно, с записью причины в evidence.
- [ ] Мягкий порог не останавливает, но фиксирует предупреждение ровно один раз за прогон.
- [ ] Существующие поля `tokenBudgetPerRun` / `maxRunCostUsdMicro` продолжают работать.

## Тесты
- Юнит: пересечение порогов; несколько уровней одновременно; сброс на новом прогоне.
