# 0804 — Идемпотентность постановки в очередь

**Фаза:** P1 · **Оценка:** S · **Зависит от:** 0803
**Файлы:** `packages/state/src/queue/postgres-run-queue.ts`, `packages/core/src/idempotency/build-idempotency-key.ts`

## Контекст
В домене уже есть построитель ключей идемпотентности и dedup-registry с lease-владельцем —
их надо переиспользовать, а не заводить второй механизм.

## Задача
Ключ постановки строится из `(tenantId, projectId, taskId, agentRef, триггер)`;
повторный триггер (webhook-ретрай, двойной клик в UI, cron-дубль) не создаёт второй прогон.

## Критерии приёмки
- [ ] Уникальный индекс БД — единственный источник истины (без проверки «сначала SELECT»).
- [ ] Повтор после завершения работы допускается только при явном `forceNewRun`.
- [ ] Ключ детерминирован и воспроизводим (тест на стабильность хеша).

## Тесты
- Юнит: стабильность ключа; интеграция: две параллельные постановки → одна запись.
