# 0701 — Фабрика рантайма на проект

**Фаза:** P0 · **Оценка:** L · **Зависит от:** 0104, 0106, 0202, 0505
**Файлы:** `packages/runtime/src/index.ts`

## Контекст
`createRuntimeApplicationContext` создаёт состояние с фиксированным `projectId`
(`packages/runtime/src/index.ts:57`) и один LLM-клиент на процесс (строка 84).

## Задача
Переписать композицию так, чтобы контекст собирался под конкретный `RunContext`, а тяжёлые
ресурсы (пул БД, реестр провайдеров, реестр инструментов) переиспользовались между проектами.

## Объём
- `createInstanceRuntime(instanceConfig)` — общие синглтоны: пул Postgres, `ProviderRegistry`,
  `CredentialStore`, `ObservabilityStore`, `ProjectCatalogStore`.
- `createProjectRuntime(instanceRuntime, scope)` — `bindScope(...)`, эффективный конфиг проекта,
  `Orchestrator` под этот скоуп.
- Кэш проектных рантаймов с инвалидацией при смене версии конфига проекта.

## Критерии приёмки
- [ ] Один процесс держит N проектов; пул соединений один, не N.
- [ ] Смена `ProjectConfig` инвалидирует кэш и применяется к следующему прогону.
- [ ] Существующие CLI-команды работают, подставляя проект по умолчанию.

## Тесты
- Интеграция: 3 проекта в одном процессе, независимые прогоны, счётчик соединений не растёт линейно.
