# 0905 — Режимы shared / exclusive в lock-store

**Фаза:** P1 · **Оценка:** M · **Зависит от:** 0903
**Файлы:** `packages/state/src/locks/distributed-lock.store.ts`, адаптеры postgres/redis/etcd

## Задача
Добавить в существующий distributed lock разделяемый режим (много читателей / один писатель).

## Объём
- Postgres: счётчик держателей + условное обновление в транзакции (или advisory locks).
- Redis: отдельный счётчик + writer-флаг; аккуратно с TTL и отказами.
- etcd: аналогично, через ревизии.
- Fencing token сохраняется для exclusive; для shared — версия набора держателей.

## Критерии приёмки
- [ ] Писатель не получает лок, пока есть активные читатели, и наоборот.
- [ ] Просроченный читатель не блокирует писателя навсегда (TTL + reaper).
- [ ] Существующие exclusive-сценарии не изменили поведение.

## Тесты
- Интеграция для каждого адаптера: N читателей + писатель; истечение TTL читателя.
