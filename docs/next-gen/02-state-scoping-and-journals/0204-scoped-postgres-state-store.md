# 0204 — Скоупированный PostgresStateStore

**Фаза:** P0 · **Оценка:** L · **Зависит от:** 0105, 0203
**Файлы:** `packages/state/src/postgres/PostgresStateStore.ts`

## Задача
Реализовать `ScopedStateStore` поверх Postgres: все запросы фильтруются по
`(tenant_id, project_id)`, снимок сохраняется с optimistic concurrency в рамках скоупа.

## Объём
- Все `SELECT`/`INSERT` получают скоуп в `WHERE`/`VALUES`.
- `save` использует уникальность `(tenant_id, project_id, revision)` вместо глобальной.
- Журнальные `append*` — отдельные вставки, без перезаписи снимка.
- Пул соединений один на процесс, а не на проект (проверить текущую реализацию `pg.ts`).

## Критерии приёмки
- [ ] Два проекта в одной БД полностью изолированы: запись в A не меняет ревизию B.
- [ ] Конфликт ревизий внутри одного проекта по-прежнему приводит к ошибке конкурентности.
- [ ] `tests/state-store.test.ts` проходит через `bindScope`.

## Тесты
- Интеграция: параллельная запись в два проекта; конфликт внутри одного; счётчик соединений.

## Не входит
- Удаление журнальных массивов из снимка (2401).
