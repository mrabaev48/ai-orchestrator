# 1606 — Пайплайн валидации при публикации агента

**Фаза:** P2 · **Оценка:** M · **Зависит от:** 1604, 1605
**Файлы:** `packages/application/src/agents/validate-agent.ts`

## Шаги валидации
1. zod-схема определения.
2. Ссылочная целостность: существуют ли `skills`, `mcpServers`, `rules`, `routingRuleId`,
   доступны ли указанные модели.
3. Проверка неэскалации прав относительно `ProjectConfig` (1605).
4. Компиляция выходной JSON Schema и регистрация в `role-output-schema-registry`
   (`packages/core/src/role-output-schema-registry.ts`), проверка strict-совместимости.
5. Dry-run на фикстуре (1611).

## Критерии приёмки
- [ ] Отчёт валидации перечисляет все проблемы разом, а не первую (как это делает `ConfigError`).
- [ ] Публикация невозможна при любой ошибке; предупреждения не блокируют.
- [ ] Результат валидации сохраняется вместе с версией (для аудита).

## Тесты
- Юнит: каждая проверка по отдельности; агрегированный отчёт.
