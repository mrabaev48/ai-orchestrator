# 0103 — Инвариант «дочерняя политика только сужает»

**Фаза:** P0 · **Оценка:** S · **Зависит от:** 0102
**Файлы:** `packages/core/src/config/narrow-policy.ts` (новый)

## Контекст
Как только конфигурация проекта и агента станет данными, появится канал эскалации привилегий:
агент сможет расширить себе `writeMode` или снять `approvalRequiredActions`. Это надо закрыть
на уровне контракта, а не ревью.

## Задача
Реализовать `narrowToolPolicy` / `narrowWorkflowPolicy`, которые допускают только сужение
ограничений безопасности и бросают `PolicyEscalationError` при попытке расширения.

## Объём
- Частичный порядок на `SafeWriteMode`:
  `read-only < propose-only < sandbox-write < workspace-write < protected-write`.
- `allowedShellCommands`, `allowedWritePaths` — только подмножество родителя.
- `protectedWritePaths`, `approvalRequiredActions` — только надмножество родителя.
- Числовые лимиты (`maxModifiedFiles`, `maxSteps`, бюджеты) — только меньше или равно.
- Новый класс ошибки `PolicyEscalationError` в `packages/shared/src/errors`.

## Критерии приёмки
- [ ] Любая попытка расширения прав отклоняется с указанием конкретного поля.
- [ ] Функция чистая, без обращения к состоянию.
- [ ] Покрытие ветвей 100% (это защитный инвариант).

## Тесты
- Юнит-матрица по каждому полю: сужение — ок, расширение — ошибка, равенство — ок.

## Не входит
- Применение при публикации агента (1605).
