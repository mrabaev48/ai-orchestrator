# 1302 — Мост к нативному tool-calling

**Фаза:** P1 · **Оценка:** L · **Зависит от:** 1301, 1205
**Файлы:** `packages/execution/src/roles/tool-bridge.ts`

## Задача
Передавать доступные инструменты как `tools` запроса и исполнять `toolCalls` ответа через
`ToolRegistry`, вместо самодельной схемы `request_tool`.

## Объём
- Маппинг `ToolDescriptor → ToolSpec` (JSON Schema из `packages/tools/src/contracts/input-output-schemas.ts`).
- Исполнение вызова под существующими гейтами (preflight/step/postflight), dedup и evidence.
- Фолбэк для моделей без tool-calling: текущая схема `request_tool` сохраняется как стратегия.

## Критерии приёмки
- [ ] Лимит шагов, wall-time и отмена работают так же, как сейчас.
- [ ] Каждый вызов инструмента даёт запись в run-step-log с тем же форматом.
- [ ] Модель без tool-calling автоматически идёт по фолбэку (метрика фиксирует это).

## Тесты
- Интеграция на кассетах: цикл с двумя вызовами инструментов; фолбэк-режим; отмена в середине.
